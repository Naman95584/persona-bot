# Persona Bot: a Voice Bot persona that fits each seller and adapts mid-call

**IndiaMART Voice AI Hackathon 2.0 · Problem 4: Persona Design** · built on Sarvam (Saaras STT, Sarvam-M LLM, Bulbul TTS)

Before each call, we generate a persona from the seller's data and from evidence mined out of past calls: voice, pace, language, formality, tone, opening line, objection playbook and guardrails, **each with a reason**. During the call, we detect **rush, confusion, frustration, interest and language switches**, change the persona on the fly, and log every switch.

## Quick start (5 commands)
```bash
pip install -r requirements.txt
cp .env.example .env              # put SARVAM_API_KEY=... in .env (leave empty for offline MOCK mode)
python -m persona_bot.cli all     # synthetic data → evidence → personas → scenario replays
MOCK=1 python -m pytest -q        # 18 tests
python -m persona_bot.cli serve   # open http://localhost:8000
```

## What the jury asked for → where it is
| Expected output | Where |
|---|---|
| Persona generator running on sample seller files | `python -m persona_bot.cli personas` → `outputs/personas/*.json` |
| Persona spec per seller, with the reason for each choice | every field has `reason.why` and `reason.source` (seller field or evidence stat) |
| Live demo with ≥1 mid-call switch | web UI; scripted demo lines in `tests/scenarios/` |
| Switch log: signal detected, change made, reason | `outputs/switch_logs/<call_id>.jsonl` (+ confidence, quoted trigger words, latency) |
| Support from past-call evidence | `evidence/summary.md`, `evidence/persona_effects.json` |

## How it works
```
 past calls ─► traits.py ─► miner.py ─► evidence (rate, n, CI; shrinkage + FDR + Simpson guard)
                                              │
 seller file ───────────────────────────► generator.py ─► persona spec (every field has a reason)
                                                                │
 seller speaks ─► Saaras STT ─► signal_detector ─► persona_policy ─► prompt rebuilt ─► Sarvam-M ─► Bulbul TTS
                                                      │ (hysteresis, cooldown, priority, two channels)
                                                      └─► switch log
```
Full walkthrough of every file and decision: **[docs/GUIDE.md](docs/GUIDE.md)**. Approach note: **[docs/APPROACH.md](docs/APPROACH.md)**.

## Sarvam Voice Agents
Each demo seller (R001 busy, R004 new/confused, R007 frustrated/language-mixing) also has a Sarvam Voice Agent. The agent is
generated from our persona spec with `python -m persona_bot.export_agent <id>` (greeting, language, speaker and system prompt),
while the **live mid-call persona switching runs in our app**, not in the Sarvam agent. Agent IDs and how each was built:
**[docs/SARVAM_AGENTS.md](docs/SARVAM_AGENTS.md)**.

## Data
`data/samples/` and `data/past_calls.csv` are **synthetic** (generated by `persona_bot/data/synth.py` with planted effects, so we can verify the miner recovers them). Real seller data stays in `data/raw/` (gitignored), per the "no customer data leaves the premises" rule.
